# The docs-agent lab (G-316)

`/lab/docs`, `php artisan lab:docs-run` and `php artisan lab:docs-certify`
exercise [`particle-academy/prism-agent-docs`](https://github.com/Particle-Academy/prism-agent-docs),
the Word-document subagent, the way Fancy's Charlotte lab exercises Charlotte:
a test is a **brief plus lanes**, every lane **writes and re-reads a real
file**, grading is **structural checks plus a model judge**, and runs and
**certificates are recorded**. The owner's rule for this agent is that
nothing ships until it is proven here.

The agent is installed from the sibling working tree (`../prism-agent-docs`,
a composer path repository, `dev-main as X.Y.Z`), so the lab tests the code
before it is published.

## Scenarios are data

Everything a scenario is lives in `resources/docs-lab/`, versioned:

| file | what it holds |
|---|---|
| `scenarios/<ID>.json` | `id`, `version`, `title`, `origin`, the `brief` (the person's words), the `store` (the lab documents in the saved slot and the pending-draft slot), `expect` (the structural checks), `judge` (the expectation the judge grades against) and `scripted` (the tool calls the free lane plays) |
| `documents/<name>.json` | a last-word document model; a picture is written `"src": "png:NAME"` |
| `pictures.json` | each picture as width, height and one RGB colour; the PNG is generated byte by byte |

No binary file is committed and no customer file exists: the source `.docx` is
written by last-word from the model on every run, and pictures are graded by
the sha256 of the bytes `Fixtures` generates. A scenario's **digest** covers its
own file, the documents it names and the picture definitions; edit any of them
and the digest moves, and an old certificate no longer matches.

| id | from | asks | passes when |
|---|---|---|---|
| S1 | Moic | revise a letterhead whose logo and divider sit in the page header | the header holds both pictures (same bytes, same order), nothing else holds a picture, the body is empty, the footer is the saved one, `margins.header` is 0, no `image_unknown` ever, the message is exactly "The draft is ready." |
| S2 | Moic | an edit with an EMPTY pending draft | the model was shown the SAVED file (both header pictures named), the draft slot now holds the new draft, `baseVersion` is the saved file's |
| S3 | Moic | "Use no margins for the header" on a body-designed letterhead | the `side-margins-shared` limit is reported, the message is the limit plus the offered alternative in the catalogue's words, no margin changed, no no-op draft, at most 4 model calls |
| S4 | new | the same ask on the header letterhead | `margins.header` IS set to 0 (the expressible part), the side margins are not (offered, never applied), header and footer kept, the message is "The draft is ready." plus the limit and the offer |
| R1 | owner rule | rewrite the letter, saying nothing of the header | header and footer identical to the saved file, body rewritten |
| R2 | owner rule | change the heading AND ask for something impossible | the message is exactly "The draft is ready." plus what could not be done; nothing narrated |

## Lanes

**`scripted`** — free, deterministic, no network, runs in CI. Each scenario's
`scripted` turns are played by `App\DocsLab\ScriptedModel`, Prism's fake taught
to EXECUTE the tool calls it is scripted with against the tools the harness
resolved for the agent's session. So the agent's real `write_draft` runs,
last-word really writes the `.docx`, and the agent's self-check really re-reads
it. The lane proves the lab and the agent's seams, not a model's judgement.

**`live`** — a real provider model, PAID. It runs only from the CLI with an
owner GO, and never in CI:

1. On `/lab/docs`, *Approve a live run…* opens the Lab's paid-run approval for
   the action `cli.docs.run`. That is the approval request: the owner sees the
   frozen plan (scenarios by digest, builder and judge model, output ceiling,
   the agent's version and source digest), chooses a USD cap (at most $5, the
   Lab session limit), approves and gives GO. The page then shows the exact
   command with `--approved-run=<GO id>`. One GO buys one run, and expires 15
   minutes after it was prepared.
2. `lab:docs-run --lane=live ... --approved-run=<id>` consumes the GO
   (`ApprovedCliRun`, the same preflight as every paid CLI), re-derives the plan
   and refuses if anything moved since approval, binds one `docs.lab` paid-work
   row, and runs each scenario on a **private** harness runtime built with the
   cap as its root budget, the approved prices, and `LiveCostObserver`.
3. Every model call, builder and judge, is reserved at its worst case in
   `lab_call_reservations` against the intent's cap BEFORE it is sent, and
   settled at its real cost after. A call that would pass the cap is refused,
   the run stops, and nothing further is spent.
4. When the run is over, passed, failed or aborted, the GO is **settled**
   (`RunAuthority::settle`): its actual cost (settled calls at their charge, an
   unsettled one at its worst case) stays allocated against the $5 session
   limit, and the rest of the cap is released. Once, in one locked
   transaction, and only when its `docs.lab` work row is finished. A settled
   GO authorises nothing more. Only `cli.docs.run` is settleable
   (`RunAuthority::SETTLEABLE`): its every paid call is on the ledger.

GOs used before settlement existed kept their whole caps. `lab:settle-runs`
lists them with what each would release; `lab:settle-runs --apply` settles them
through the same path. It runs no SQL of its own, and a second run releases
nothing.

`lab:docs-run` cannot create, approve or widen an intent. Without a GO it
prints `paid_call_not_authorised` and does nothing.

The owner can also approve in Genie, by answering a ForceTheQuestion. The local
operator records that answer with `lab:approve-from-ftq --action=cli.docs.run`,
using the same scenario, model, judge and cap options. The plan, the checks and
the single 15-minute GO are the same as on the page. The question id and the
answer are stored on the intent for audit. The Lab cannot verify the answer
itself, so this trusts the local operator; see the README.

## Grading

A scenario **passes only if every structural check passes and, when the judge
ran, the judge said pass**. A judge that could not answer leaves it unjudged,
which is not a pass.

**Structural** (`App\DocsLab\Checks`): read from the `.docx` on disk with
last-word's reader. Pictures by sha256 per part, margins, band presence and
equality with the working copy's band, empty body, no first-page band, text
present, the limit reported, the model-call count, and the message compared
EXACTLY against the sentences the agent's own `limits.json` allows. The tool
calls and results are read back from the harness thread the agent ran on, the
same way in both lanes.

**Judge** (`App\DocsLab\Judge`, live only, same approval and cap): the brief,
the scenario's `judge` expectation, the working copy and the draft as last-word
reads them (every picture replaced by its sha256), the outcome and the message.
It never sees the builder's conversation. It answers `pass`/`fail` and a reason
through a structured schema.

## Records

Additive migration `2026_11_21_000001_create_docs_lab_tables`:

- `docs_lab_runs`: lane, selection, status (`passed` / `failed` / `stopped`),
  the agent (`version`, `pretty`, `reference`, `source_digest`), models, the
  intent, the settled cost.
- `docs_lab_results`: per scenario, the digest, outcome, message, every check
  with its detail, the judge's verdict and reason, the tool calls, artefacts
  with their sha256.
- `docs_lab_certificates`: the chain below.

Artefacts are files under `config('docs-lab.artefacts')`
(`storage/app/docs-lab/runs/<run>/<scenario>/`): `source.docx`, `draft.docx`,
`draft.json` (the re-read model, pictures as sha256) and `result.json`. The page
serves one only to the owner, and only while it still matches the recorded
sha256.

`source_digest` is sha256 over every file the agent ships (`src/`,
`resources/`, `composer.json`) as installed, so an uncommitted edit in the
sibling tree is a different agent.

## Certificates

`lab:docs-certify [--run=<id>]` issues one for a live run that passed every
current scenario at its current digest, structurally AND by the judge, made
against exactly the agent bytes installed now. `--verify` walks the chain.

Format `prism-labs/docs-agent-certificate@1`, written to the table and to
`<artefacts>/certificates/NNNN-prism-agent-docs-<version>.json`:

```json
{
  "format": "prism-labs/docs-agent-certificate@1",
  "sequence": 1,
  "previous": null,
  "issuer": "prism-labs",
  "subject": { "package": "particle-academy/prism-agent-docs", "version": "0.1.6", "reference": "<commit>", "source_digest": "<sha256>" },
  "evidence": {
    "run": "<run id>", "lane": "live", "intent": "<GO id>",
    "provider": "anthropic", "model": "...", "judge_model": "...", "cost_microusd": 123456,
    "started_at": "...", "finished_at": "...",
    "scenarios": [ { "id": "S1", "version": 1, "digest": "<sha256>", "structural": "pass", "judge": "pass", "artefacts": { "draft.docx": "<sha256>" } } ]
  },
  "issued_at": "...",
  "hash": "<sha256>"
}
```

`hash` = sha256 of the canonical JSON (keys sorted at every depth, no
whitespace, slashes and Unicode unescaped) of every field except `hash`.
`previous` is the previous certificate's `hash`. Editing, removing or
reordering any certificate breaks its own hash or the next one's link.

Charlotte signs with Ed25519 and a key in the lab's `.env`. This chain needs no
secret and proves nothing about who issued it; if a certificate is ever handed
to someone as evidence on its own, add a signature.

## Tests

`tests/Feature/DocsLab/`, on forced in-memory SQLite (asserted before a plain
`migrate`; nothing is wiped):

- `ScriptedLaneTest`: every scenario passes on the scripted lane, from files;
  a positive control proves the grading fails a run that drafted nothing.
- `ScriptedLaneMutationTest`: a copy of the agent's `PictureRegistry` that
  registers only BODY pictures (Moic's original host bug) is loaded in a child
  process; S1 must fail with `image_unknown`, R2 (body pictures only) must pass.
- `LiveLaneAuthorityTest`: refused without approval or with a forged one; an
  approved run reserves and settles every call; the cap stops a run before an
  unaffordable call, both per scenario (harness budget) and across scenarios
  (the ledger); one GO, one plan, one run; a judge fail fails the scenario.
- `RunSettlementTest`: a finished run releases its cap minus what it spent;
  nothing is released twice; a run the cap stopped releases everything; an
  aborted run is settled at what it spent; an unsettled call is kept at its
  worst case; work in flight keeps the whole cap; `lab:settle-runs` lists
  without changing and settles with `--apply`.
- `FtqOwnerApprovalTest`: a GO recorded from an FTQ answer lets exactly one
  run; a second use, a wrong action, cap or plan, a reused question id and an
  expired GO are refused; local console only.
- `CertificatesTest` and `DocsLabPageTest`.

The live lane is only ever exercised with Prism's fake in tests.
